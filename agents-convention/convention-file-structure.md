# Структура файла конвенции

## Назначение
Задаёт единый формат для файлов конвенций в пакете agents-convention, чтобы каждая конвенция описывала один узкий кейс и была одинаково устроена.

## Когда применять
При создании нового файла конвенции в agents-convention и при проверке, что существующий файл конвенции соответствует формату.

## Что разрешено
- Один файл — один узкий кейс.
- Фиксированный порядок секций верхнего уровня: Название, Назначение, Когда применять, Что разрешено, Что не разрешено, Названия, Пример, Связанные конвенции.
- Секция "Связанные конвенции" содержит список ссылок на другие файлы конвенций или прочерк "—", если связей нет.
- Ссылаться на другие конвенции по имени файла (например, `convention-file-structure.md`).

## Что не разрешено
- Описывать в одном файле несколько не связанных друг с другом кейсов.
- Пропускать секцию "Пример".
- Менять порядок секций или добавлять новые секции верхнего уровня.
- Использовать общие, "резиновые" названия секций или формулировки без конкретики.

## Названия
- Имя файла конвенции: kebab-case, отражает узкий кейс, без общих слов вроде `rules`, `guide`, `misc`. Пример: `compose-widget-naming.md`, а не `compose.md`.
- Конвенция уровня фичи: `feature-<тема>.md`. Если тема — конкретный архитектурный слой (data, domain, presentation и т. п.) — `feature-layer-<слой>.md` (`feature-layer-data.md`, `feature-layer-domain.md`). Если тема — сквозной технический аспект фичи (router, di и т. п.) — без `layer`: `feature-router.md`, `feature-di.md`; уточнения этого аспекта (провайдеры, ключи и т. п.) не выносятся в имя файла, а описываются внутри.
- Конвенция про build-logic (`build-logic/`): `buildlogic-<тема>.md` (например `buildlogic-plugin-naming.md`, `buildlogic-plugin-structure.md`).
- Заголовок в начале файла: `# ` + название конвенции человекочитаемым текстом, по смыслу совпадающее с именем файла.

## Пример
Файл `uikit-widget-suffix.md`:

```
# Суффикс Widget для компонентов uikit

## Назначение
Отличает переиспользуемые UI-компоненты uikit (framework/uikit) от обычных composable-функций экрана по имени.

## Когда применять
При создании нового публичного composable-компонента в модуле framework/uikit.

## Что разрешено
- Называть composable-функцию и файл с суффиксом `Widget`: `AppButtonWidget`, `AppTopBarWidget`.
- Имя файла совпадает с именем функции.

## Что не разрешено
- Публичный composable в framework/uikit без суффикса `Widget`.
- Суффикс `Widget` у composable вне framework/uikit (в feature-модулях используется своё соглашение).

## Названия
Имя = `App` + смысловое имя + `Widget`, например `AppButtonWidget`, `AppTopBarWidget`.

## Пример
`framework/uikit/.../AppButtonWidget.kt`:
fun AppButtonWidget(modifier: Modifier = Modifier, text: String, ...)

## Связанные конвенции
—
```
